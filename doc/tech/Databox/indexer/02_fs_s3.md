# FS and S3/AMQP locations

This page documents the `fs` and `s3_amqp` location types used by the Databox indexer.

## Terminology (code-aligned)

- Location type `fs`: local filesystem source.
- Location type `s3_amqp`: S3 events consumed from AMQP queue.
- Main commands:
  - `index <location-name>`
  - `watch`
  - `list`
- Optional command:
  - `index-all` (batch run on all configured locations)

## `fs` location

### Purpose

Import files from a local directory into Databox and keep Databox synchronized with filesystem changes.

### Required options

- `workspaceSlug`
- `dir`

### Optional options

- `dirPrefix`: replaces `dir` at the start of the path of the assets (their key and their
  collection path), e.g. `fs` for `/fs-watch/a/b.jpg` → `fs/a/b.jpg`;
- `sourceDir`: replaces `dir` in the source path of the assets (`${sourcePath}` of the
  `alternateUrls`), i.e. where the files are on the host;
- `createNewWorkspace`: flush the workspace before an `index` (as `index -n`).

The workspace is created if it does not exist.

### Example

```json
{
  "name": "my_fs",
  "type": "fs",
  "options": {
    "dir": "%env(WATCH_DIR)%",
    "dirPrefix": "%env(WATCH_DIR_PREFIX)%",
    "sourceDir": "%env(WATCH_SOURCE_DIR)%",
    "workspaceSlug": "%env(DATABOX_WORKSPACE_SLUG)%"
  },
  "alternateUrls": [
    {
      "name": "indexer",
      "pathPattern": "indexer://${sourcePath}"
    }
  ]
}
```

### Runtime behavior

- `index <location-name>`:
  - walks `dir` recursively;
  - creates or updates an asset per file, keyed by its path, in the collections matching its
    directories; its source file is a URL of the asset HTTP server of the indexer
    (see [Asset HTTP server](./01_intro.md#asset-http-server)).
- `watch` for `fs` (existing files are not indexed again):
  - listens for file events;
  - `add` creates or updates the asset;
  - `unlink` deletes the asset of the same key.

## `s3_amqp` location

### Purpose

Consume S3 object events from AMQP and apply create/delete synchronization in Databox.

### Required options

- `workspaceSlug`
- `amqp.dsn`
- `s3.endpoint`
- `s3.bucketNames` (comma-separated; for `watch`, an empty list accepts the events of every
  bucket)
- `s3.accessKey`
- `s3.secretKey`

### Example

```json
{
  "name": "test-s3",
  "type": "s3_amqp",
  "options": {
    "amqp": {
      "dsn": "%env(AMQP_DSN)%"
    },
    "s3": {
      "endpoint": "%env(S3_ENDPOINT)%",
      "bucketNames": "%env(BUCKET_NAMES)%",
      "accessKey": "%env(S3_ACCESS_KEY)%",
      "secretKey": "%env(S3_SECRET_KEY)%"
    },
    "workspaceSlug": "%env(DATABOX_WORKSPACE_SLUG)%"
  }
}
```

The workspace must exist: it is not created.

### Runtime behavior

- `index <location-name>`:
  - lists the objects of each bucket (an iterator over `listObjectsV2`) and indexes one asset
    per object, keyed by its path, as they come; its source file is a URL of the asset HTTP
    server of the indexer, which redirects to a signed URL of the bucket
- `watch` for `s3_amqp`:
  - listens to AMQP queue `s3events`
  - handles creation events:
    - `s3:ObjectCreated:Put`
    - `s3:ObjectCreated:Post`
    - `s3:ObjectCreated:CompleteMultipartUpload`
    - `s3:ObjectCreated:Copy`
  - handles deletion event:
    - `s3:ObjectRemoved:Delete`

## Operational notes

- Keep `workspaceSlug` stable for a given location, otherwise idempotence can break.
- Ensure the bucket list and the `whitelist` / `blacklist` expressions are correct before
  enabling `watch`.
- Do not store raw credentials in committed config files; use environment variables.
