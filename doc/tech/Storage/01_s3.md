# S3 Storage

## Buckets description

The stack requires several S3 buckets.

 - phrasea-databox
   - Stores databox files and renditions referenced by assets.
   - Can be exposed through a CDN.
   - Is private, and access is performed through signed URLs.

 - phrasea-statics
   - Stores static files used by Phrasea modules, including:
     - Databox, Expose, and Uploader MUI themes.
     - Logos used on Keycloak login pages.
     - Interface design customization files and rendition watermark files.
   - Requires public access.
   - Setting CORS rules to limit allowed origins is recommended.
 
 - phrasea-uploader
   - Stores files uploaded through Phrasea Uploader.
   - Is private, and access is performed through signed URLs.

 - phrasea-expose
   - Stores files used by the Phrasea Expose module.
   - Can be exposed through a CDN.
   - Is private, and access is performed through signed URLs.

Bucket naming is flexible, but bucket names must be reported in the stack configuration.
See [environment configuration variables](../Configuration/env_var), especially the [S3-Compatible Storage Settings](../Configuration/env_var#s3-compatible-storage-settings) section.

## S3 Addressing Style

The S3 client addressing style must match your object storage provider behavior.

- `S3_USE_PATH_STYLE_ENDPOINT=true` means path-style addressing (bucket name after the endpoint domain).
- `S3_USE_PATH_STYLE_ENDPOINT=false` means virtual-hosted-style addressing (bucket name as a subdomain).

For the environment variable reference, see [Environment Variables](../Configuration/env_var#s3-compatible-storage-settings).


In Helm deployment values, the equivalent setting is `usePathStyleEndpoint`.

## Multipart Upload Settings

Phrasea uploads large files using S3 multipart upload.

The **API decides the part size**: when a client creates an upload (`POST /uploads` with the file size), the API computes the smallest part size (at least `S3_MULTIPART_MIN_CHUNK_SIZE`) that fits the file in `S3_MULTIPART_MAX_PART_NUMBER` parts, creates the S3 multipart upload and answers with `chunkSize` and the presigned `PUT` URL of **every part** (`urls`, keyed by part number). Clients then upload the parts directly to the storage, several in parallel, without asking the API for each URL.

Part URLs are valid for 3 hours. `POST /uploads/{id}/parts` (body `{"from": <part number>}`) returns fresh URLs from that part to the last one, together with `chunkSize` and `partCount`; clients use it to resume an interrupted upload or after a URL expired during a long transfer. The part size is persisted with the upload so a resumed upload keeps the same slicing even if these limits are reconfigured in between.

Every client goes through one of two shared implementations of this protocol: the JS engine exported by `@alchemy/api` (`lib/js/api/src/multiPartUpload.ts`, transport-agnostic, used by the databox, uploader and databox Next.js clients; axios clients go through `src/axiosMultipartUpload.ts`) and, for server-to-server pushes (e.g. databox publishing to expose), the PHP service `Alchemy\CoreBundle\Upload\MultipartUploader`.

Depending on your filer or object storage provider, you may need to adjust multipart limits to match platform capabilities. These variables are read by the API containers (databox, expose, uploader):

- `S3_MULTIPART_MIN_CHUNK_SIZE` (default 5 MiB, the S3 minimum)
- `S3_MULTIPART_MAX_CHUNK_SIZE` (default 5 GiB)
- `S3_MULTIPART_MAX_PART_NUMBER` (default 10 000)
- `S3_MAX_OBJECT_SIZE` (also read by the clients to reject oversized files before uploading)

If these values do not match your storage limits, uploads can fail for large files.

For variable definitions, see [Environment Variables](../Configuration/env_var#s3-compatible-storage-settings).


## Bucket CORS Configuration

If a bucket is accessed through cross-origin XMLHttpRequest calls, you must enable CORS for that bucket.

CORS Example :

```json
{
  "CORSRules": [
    {
      "AllowedHeaders": ["*"],
      "AllowedMethods": ["GET", "HEAD", "PUT", "POST", "DELETE"],
      "AllowedOrigins": ["https://*.mydomain.com"],
      "ExposeHeaders": ["ETag", "x-amz-version-id"],
      "MaxAgeSeconds": 3000
    }
  ]
}
```
